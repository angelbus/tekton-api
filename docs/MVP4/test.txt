Performance Impact

The current implementation performs a linear search over the Parquet schema to locate each required business field, resulting in a time complexity of O(M × N), where M is the number of required fields and N is the number of columns in the Parquet schema. Although this lookup is executed only once per Parquet file, it still performs repeated string comparisons and schema traversals. By introducing a Schema Registry and building an in-memory column lookup map (std::unordered_map<std::string, int>) during initialization, XDE resolves all subsequent column accesses in O(1) time. This shifts the schema discovery cost to a one-time initialization step, eliminates repeated searches, and provides a scalable foundation for future schema evolution while preserving the high-throughput processing requirements of large FMTM books (up to ~49,000 deals) and Row Group Distribution.
